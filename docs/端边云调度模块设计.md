## 6.1 资源环境建模

系统部署于终端、边缘、云端三层异构算力环境。令资源层集合 $L=\{\ell_{\text{end}},\ell_{\text{edge}},\ell_{\text{cloud}}\}$。每层资源 $\ell\in L$ 由五元组刻画：

$$
\ell=\langle C_\ell,\; M_\ell,\; \delta_\ell,\; p_\ell,\; \Phi_\ell\rangle
$$

| 符号 | 含义 | 单位 |
|------|------|------|
| $C_\ell$ | 可用算力（推理吞吐） | tokens/s 或 TFLOPS |
| $M_\ell$ | 可用显存/内存预算 | GB |
| $\delta_\ell$ | 任务源到该层的往返通信时延 | ms |
| $p_\ell$ | 单位计算成本 | ¥/1K tokens |
| $\Phi_\ell=\{m_{\ell,1},\dots,m_{\ell,n_\ell}\}$ | 该层可部署模型集合 | — |

每个模型 $m\in\Phi_\ell$ 进一步以三元组 $m=\langle P_m, W_m, \kappa_m\rangle$ 刻画：$P_m$ 为参数量，$W_m$ 为上下文窗口，$\kappa_m$ 为能力画像（对各任务类型的质量得分）。资源状态随时间演化，记 $C_\ell(t)$ 为 $t$ 时刻可用算力，由节点心跳与负载探针动态感知（节点增减、算力波动均反馈至调度器）。

**资源参数表（参考典型配置，源自 EdgeShard / QLMIO 实测口径）：**

| 层 | 典型设备 | $C_\ell$ | $M_\ell$ | $\delta_\ell$ | $p_\ell$ | $\Phi_\ell$（示例） |
|----|---------|----------|----------|--------------|----------|---------------------|
| 终端 $\ell_{\text{end}}$ | 手机/PC/NPU | 1–10 TFLOPS | 8–16 GB | <5 ms（本地） | ≈0（电费摊销） | 1–3B 量化模型 |
| 边缘 $\ell_{\text{edge}}$ | 边缘服务器/Jetson Orin | 10–100 TFLOPS | 16–32 GB | 5–20 ms | 低 | 3–8B 模型 |
| 云端 $\ell_{\text{cloud}}$ | A100/H100 集群 | 100+ TFLOPS | 80 GB×N | 20–100 ms | 高（按 token 计） | 30B–175B 大模型 |

> 该表为初版参考值；最终数值将依团队实际算力资源与演示环境标定，并在评测阶段回填。终端层 $p_\ell\approx 0$ 是端侧调度的天然成本优势，亦是隐私约束下敏感任务的承载层。

## 6.2 子任务特征建模

每个子任务 $w\in W$ 以特征向量 $\mathbf{f}_w=(s_w,\tau_w,\sigma_w)$ 刻画，分别对应计算规模、实时性要求与数据敏感等级。特征值由规划器（#1）在分解 DAG $D=(W,A)$ 时预估，并随执行反馈（#4）在线校正。

**（1）计算规模 $s_w$**：量化为预期推理 token 数与推理深度（链式步数）的乘积，分四级。

| 等级 | 定义 | 典型场景 |
|------|------|---------|
| $S_0$ 轻量 | <2K token·步 | 单轮问答、格式转换 |
| $S_1$ 中等 | 2K–8K | 单函数生成、文档摘要 |
| $S_2$ 重型 | 8K–32K | 跨文件代码修改、多文档综合 |
| $S_3$ 超重型 | >32K | 仓库级重构、长程投研 |

**（2）实时性要求 $\tau_w$**：时延预算（ms），分四级。

| 等级 | 定义 |
|------|------|
| $T_0$ 交互级 | <500 ms |
| $T_1$ 秒级 | 0.5–2 s |
| $T_2$ 分钟级 | 2–60 s |
| $T_3$ 批处理 | >60 s |

**（3）数据敏感等级 $\sigma_w$**：决定可承载位置的硬约束。

| 等级 | 定义 | 允许位置集合 $L_w(\sigma_w)$ |
|------|------|------------------------------|
| $L_0$ 公开 | 公开数据/无敏感性 | $L$（三层均可） |
| $L_1$ 内部 | 内部非敏感数据 | $L$（三层均可） |
| $L_2$ 敏感 | 含个人/商业敏感信息 | $\{\ell_{\text{end}},\ell_{\text{edge}}\}$（禁上云） |
| $L_3$ 机密 | 含强合规要求数据 | $\{\ell_{\text{end}}\}$（仅端侧） |

> 隐私约束是位置分配的**硬约束**：$\sigma_w\in\{L_2,L_3\}$ 的子任务不得上传云端，相应数学表达在 §6.4 与总体优化模型 §11 中给出。

## 6.3 调度决策与模型切分

### 6.3.1 调度决策变量

调度决策变量为总体优化模型三组决策变量之一，定义为：

- $x_{w,\ell}\in\{0,1\}$：子任务 $w$ 是否分配至层 $\ell$；满足唯一分配约束 $\sum_{\ell\in L}x_{w,\ell}=1$。
- $z_{w,m}\in\{0,1\}$：子任务 $w$ 选用模型 $m$；满足 $\sum_m z_{w,m}=1$，且 $z_{w,m}=1\Rightarrow m\in\Phi_\ell$（其中 $\ell$ 满足 $x_{w,\ell}=1$）。
- $\pi_w$：模型切分方案。层切分时 $\pi_w=(b_1,\dots,b_{K-1})$ 为各参与层的 transformer 块数分配（$\sum b_i = K$，模型总块数）；阶段切分时 $\pi_w\in\{(\ell_{\text{pre}},\ell_{\text{dec}})\}$ 指定 prefill 与 decode 的承载层。

### 6.3.2 两阶段调度策略

调度以"子任务量"（$s_w$）与"任务隐私程度"（$\sigma_w$）为主轴，$\tau_w$ 为时延边界，采用两阶段决策：

**阶段一 · 可行域筛选（硬约束）**
1. 隐私硬筛：依 $\sigma_w$ 确定 $L_w(\sigma_w)$，剔除不允许的层。
2. 能力与容量筛选：在 $L_w$ 内，仅保留存在模型 $m\in\Phi_\ell$ 且 $\text{CAPABLE}(m,s_w)$（计算规模在模型能力内）、且 $C_\ell(t)$ 足够的 $(\ell,m)$ 对，得可行集 $F_w$。
3. 若 $F_w=\varnothing$ 且 $s_w$ 超出任一单层承载能力 → 进入模型切分（§6.3.3）。
4. 若 $F_w=\varnothing$ 且不可切分 → 向 #1 规划器回送**调度不可行**信号，触发重规划。

**阶段二 · 成本最优选择（在线自适应）**
在 $F_w$ 中最小化调度代价函数：

$$
J(w,\ell,m)=\alpha\cdot\frac{\text{Lat}(w,\ell,m)}{\tau_w}+\beta\cdot\text{Cost}(w,\ell,m)+\gamma\cdot\big(1-\kappa_m(s_w)\big)
$$

s.t. $\text{Lat}(w,\ell,m)\le\tau_w$，其中 $\alpha,\beta,\gamma$ 为权重。直观映射：
- **高复杂度 + 低敏感**（$s_w\in\{S_2,S_3\},\sigma_w\in\{L_0,L_1\}$）→ 云端大模型（算力足、质量高，时延可接受）；
- **高实时性 或 高敏感**（$\tau_w\in\{T_0,T_1\}$ 或 $\sigma_w\in\{L_2,L_3\}$）→ 端侧/边缘小模型（低时延、数据不出域）。

**在线自适应**：资源状态 $C_\ell(t)$ 与任务到达率随时间变化，模型选择在重复同类子任务上建模为**受限 bandit**——在硬预算（packing，token 成本上限）与软 SLA（covering，时延达标率下限）约束下，用置信界估计 + 需求预测平衡探索利用，理论保证次线性 regret 与次线性约束违反。该机制使调度器从 #4 执行反馈中持续学习，实现"自适应调配"。

### 6.3.3 模型切分点选择算法

当单层无法承载 $s_w$（显存或算力不足），启用协同推理切分。设计两种正交切分模式，按场景择优或混合：

**模式 A · 层切分（Pipeline 并行，源自 EdgeShard）**
将 $K$ 层 transformer 块按 $(b_1,\dots,b_{|L'|})$ 分配到参与层 $L'\subseteq L_w$，层间经高速互联传 KV 状态。切分点选择建模为动态规划：

$$
\pi_w^{*}=\arg\min_{\pi}\sum_{i=1}^{|L'|}\frac{\text{comp}_i(b_i)}{C_{\ell_i}(t)}+\sum_{i=1}^{|L'|-1}\delta_{\ell_i,\ell_{i+1}}\cdot|\text{KV}(b_i)|
$$

DP 在块数×层数上求解，复杂度 $O(K\cdot|L'|^2)$，可离线预计算并按 $C_\ell(t)$ 在线重选。该法已在 EdgeShard 验证可降时延约 50%、吞吐翻倍。

**模式 B · 阶段切分（Prefill/Decode 解耦，源自 Splitwise/DistServe）**
将推理两阶段分到不同层：prefill（计算密集）→ 云端，decode（访存密集）→ 边缘/终端，经互联传 KV cache。利用两阶段资源特征差异，消除 prefill-decode 干扰，提升 goodput。

**混合策略**：默认按 $s_w$ 与 $\tau_w$ 在 A/B 间选择——长上下文重计算（$S_3$、$T_2/T_3$）用阶段切分榨取云端算力；中等规模但跨域协同（$S_2$、需端云共担显存）用层切分；二者均以 §6.3.2 代价函数 $J$ 为择优准则。

### 6.3.4 调度器伪代码（对应附录 A）

```
function SCHEDULE(w, 状态 C(t), 反馈历史):
    L_w ← ALLOWED_LAYERS(σ_w)                       # 隐私硬筛
    F   ← { (ℓ,m) : ℓ∈L_w, m∈Φ_ℓ, CAPABLE(m,s_w), C_ℓ(t)≥req }
    if F = ∅ and 超出单层承载(s_w):
        if 适于阶段切分(s_w,τ_w):  π ← PHASE_SPLIT_PLAN(w, C(t))   # 模式 B
        else:                       π ← EDGESHARD_DP(w, L_w, C(t))  # 模式 A
        return EXECUTE(w, location=多层, split=π)
    if F = ∅:  return INFEASIBLE → 规划器(#1) 重规划
    # 在线自适应：bandit 估计各 (ℓ,m) 奖赏，受预算/SLA 约束
    (ℓ*,m*) ← argmin_{(ℓ,m)∈F} J(w,ℓ,m)   s.t. Lat≤τ_w
    return EXECUTE(w, location=ℓ*, model=m*, split=∅)
```

## 6.4 调度性能指标

**（1）端到端时延** $\text{Lat}(w)$：子任务从分配到返回结果的总耗时。

- 单层执行：$\text{Lat}(w,\ell,m)=\delta_\ell + t_{\text{pre}}(s_w,m,C_\ell)+t_{\text{dec}}(s_w,m,C_\ell)$
- 层切分（模式 A）：$\text{Lat}=\sum_{i}\big[t_{\text{layer}}(b_i)/C_{\ell_i}(t)\big]+\sum_i\delta_{\ell_i,\ell_{i+1}}\cdot|\text{KV}_i|$
- 阶段切分（模式 B）：$\text{Lat}=\delta_{\text{pre}}+t_{\text{prefill}}(s_w,m,C_{\text{cloud}})+\delta_{c\to e}+t_{\text{decode}}(s_w,m,C_{\text{edge}})+\delta_{\text{ret}}$

全网时延取关键路径上子任务时延之和（依 DAG $D=(W,A)$ 的最长加权路径）。

**（2）资源开销** $\text{Cost}$：

$$
\text{Cost}(w,\ell,m)=\big(\text{tok}_{\text{in}}(w)+\text{tok}_{\text{out}}(w)\big)\cdot p_\ell+\text{comp}(s_w,m)\cdot c_\ell
$$

总资源开销 $\text{Cost}_{\text{total}}=\sum_{w\in W}\text{Cost}(w)$，含 Token 消耗与计算成本两部分。

**（3）隐私约束满足率** $P_{\text{priv}}$：

$$
P_{\text{priv}}=1-\frac{1}{|W|}\sum_{w\in W}\mathbf{1}\!\left[x_{w,\ell}=1\;\wedge\;\ell\notin L_w(\sigma_w)\right]
$$

即被违规分配到不允许层的敏感子任务占比的补数；$P_{\text{priv}}=1$ 表示全部敏感任务位置合规。

> 三项指标既是调度质量评价依据，亦作为总体优化模型 §11 的目标/约束分量：在 $\text{Lat}\le\tau_w$、$P_{\text{priv}}=1$、容量与预算约束下，最小化 $\text{Cost}_{\text{total}}$ 并最大化任务成功率。

## 6.5 与其它模块的接口

| 方向 | 协作方 | 内容 |
|------|--------|------|
| 输入 ← | #1 规划器 | 子任务 DAG $D=(W,A)$ 及各 $w$ 的三元组 $(s_w,\tau_w,\sigma_w)$ |
| 输入 ← | #3 记忆 | 当前工作上下文规模（影响 $s_w$ 估计）、记忆压缩/唤醒事件 |
| 输入 ← | #4 执行引擎 | 执行状态与时延/成本实测（喂入 bandit 在线学习） |
| 输出 → | #4 执行引擎 | `execute(w, location=ℓ*, model=m*, split=π_w)` |
| 输出 → | #8 路由 | 位置分配影响跨层通信拓扑生成（端↔边↔云链路） |
| 输出 → | #1 规划器 | 调度不可行反馈 → 触发重规划 |
| 输出 → | #5/#7 | 调度决策轨迹（位置/模型/切分/代价）入日志与可视化 |
| 喂入 → | §11 总体优化 | 决策变量 $x_{w,\ell},z_{w,m},\pi_w$ 与上述约束/指标 |
