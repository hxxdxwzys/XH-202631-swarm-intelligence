# 调度模块集成指南（组长对接用）

> 本指南说明**端-边-云调度模块（角色 #2）**当前状态、接口契约，以及组长整合各组成员任务时**该看什么、改什么**。
> 调度模块已自洽可运行（v0.2，1187 行 / 16 测试），对外只通过 `ports.py` 的 4 个抽象接口与其它模块交互——组长**只需替换 mock、接通真实接口**，无需改调度内部。

---

## 一、先看：调度模块现在能做什么

**一句话**：给定一个子任务（含计算规模 / 时延要求 / 数据敏感等级），输出"在哪个层、用哪个模型、是否切分"的决策；并支持从执行反馈在线学习（bandit）。

| 想了解 | 看哪里 |
|--------|--------|
| 整体设计 | `docs/端边云调度模块设计.md` §6 |
| 代码结构与复杂性 | `code/core/scheduler/README.md` |
| 跑起来看效果 | `cd code && python -m core.scheduler.sim` |
| 入口 API | `Scheduler.schedule(w)` / `AdaptiveScheduler.schedule(w)` + `feedback()` |

**核心能力**（均已实现）：
- 两阶段调度：隐私硬筛 → 可行域 → 代价函数 J / bandit 选择
- 模型切分：层切分（EdgeShard 式）+ 阶段切分（prefill/decode）择优
- 在线自适应：受限上下文 bandit（硬预算 + 软 SLA）
- 隐私硬约束：L2 禁上云、L3 仅端侧
- 推理轨迹：结构化事件日志（JSONL）
- 配置化：资源表走 `default_env.json`

## 二、接口契约（`ports.py`）—— 组长要实现/替换的 4 个接口

调度模块只通过这 4 个 Protocol 与外界交互。**当前 `sim.py` 里是 mock 实现，组长替换为真实模块即可。**

### 1. `ExecutorPort`（接 #4 执行引擎）【最关键】
```python
class ExecutorPort(Protocol):
    def execute(self, w: Subtask, decision: ScheduleDecision) -> ExecutionResult: ...
```
- **现状**：`sim.py` 的 `LocalSimExecutor` 用资源画像模拟时延/成本。
- **组长要改**：实现真实 #4 执行引擎，按 `decision`（层/模型/切分）执行子任务，返回 `ExecutionResult(success, latency_ms, cost, tokens)`。
- **关键**：真实时延和成本必须回传——bandit 的在线学习靠这个。

### 2. `PlannerPort`（接 #1 规划器）
```python
class PlannerPort(Protocol):
    def next_subtask(self) -> Optional[Subtask]: ...
```
- **现状**：演示里直接构造 `Subtask` 列表。
- **组长要改**：接 #1 规划器输出的子任务 DAG `D=(W,A)`，流式产出 `Subtask`。每个子任务需带三元组（见下）。

### 3. `MemoryPort`（接 #3 记忆）
```python
class MemoryPort(Protocol):
    def current_context_tokens(self) -> int: ...
```
- **现状**：mock 未使用。
- **组长要改**：接 #3 记忆，提供当前工作上下文 token 规模（用于修正子任务的 `est_input_tok` 估计）。若暂不接入，可留 mock。

### 4. 调度 → 路由（#8，输出方向，非 Protocol）
- 调度结果 `ScheduleDecision.layer_name` / `split` 需喂给 #8 路由模块，用于生成跨层（端↔边↔云）通信拓扑。
- 组长在编排层把 `ScheduleDecision` 传给路由模块即可。

## 五、数据结构速查

```python
# 输入（#1 规划器产出，组长构造）
Subtask(id, scale: ComputeScale, latency_tier: LatencyTier,
        sensitivity: SensitivityLevel,
        est_input_tok=1000, est_output_tok=1000, depends_on=())

# 输出（调度决策，喂 #4/#8/§11）
ScheduleDecision(subtask_id, layer_name, model_name,
                 split: SplitPlan | None, latency_ms, cost, feasible, reason)

# 切分方案
SplitPlan(mode='layer'|'phase', block_allocation=((层名,块数),...),
          phase_layers=(prefill层, decode层), model_name)

# 执行结果（#4 回传）
ExecutionResult(success, latency_ms, cost, tokens, note)
```

**枚举取值**（`models.py`）：
- `ComputeScale`: S0_LIGHT / S1_MEDIUM / S2_HEAVY / S3_XHEAVY
- `LatencyTier`: T0_INTERACTIVE(<500ms) / T1_SECOND(2s) / T2_MINUTE(60s) / T3_BATCH
- `SensitivityLevel`: L0_PUBLIC / L1_INTERNAL / L2_SENSITIVE(禁云) / L3_CONFIDENTIAL(仅端)

## 七、待团队拍板的关键参数（影响调度行为）

| 参数 | 位置 | 说明 |
|------|------|------|
| 资源参数表数值 | `default_env.json` | 按团队实际端/边/云算力标定 |
