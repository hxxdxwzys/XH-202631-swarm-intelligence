> 本指南说明**端-边-云调度模块（角色 #2）**当前状态、接口契约，以及组长整合时**该看什么、改什么**。
> 调度模块已自洽可运行（**v0.5，1884 行 / 35 测试全过**），对外通过 `ports.py` 抽象接口 + `SchedulerRuntime` 与其它模块交互。

## 二、接口契约（`ports.py` + `runtime.py`）

按**新分工 8 模块**标注对接方。新分工未单列"执行引擎/规划器"——它们属开源框架复用，由组长接线。

### 1. `ExecutorPort`（接开源执行框架）【最关键】
```python
class ExecutorPort(Protocol):
    def execute(self, w: Subtask, decision: ScheduleDecision) -> ExecutionResult: ...
```
- **现状**：`sim.py` 的 `LocalSimExecutor` 模拟执行。
- **组长要改**：接真实执行框架，返回 `ExecutionResult(success, latency_ms, cost, tokens)`。
- **关键**：真实时延和成本必须回传——bandit 在线学习靠这个。

### 2. `PlannerPort`（接开源框架/编排层的规划器）
```python
class PlannerPort(Protocol):
    def next_subtask(self) -> Optional[Subtask]: ...
```
- **现状**：`SchedulerRuntime.run(dag)` 直接接收完整 DAG 列表。
- **组长要改**：接真实规划器，产出 `Subtask`（含三元组），或直接把 DAG 列表传给 `run()`。

### 3. `MemoryPort`（接 #1 长程记忆保持）
```python
class MemoryPort(Protocol):
    def current_context_tokens(self) -> int: ...
```
- **组长要改**：接 #1 记忆模块，提供当前上下文 token 规模。

### 4. 调度 → #3 动态路由（输出方向）
- `ScheduleDecision.layer_name` / `split` 喂给 #3 生成跨层通信拓扑。

### 5. #4 智能体异构设计（输入方向）
- #4 定义角色-模型-层绑定，填入 `default_env.json` 的模型集 Φ_ℓ 与 `ModelProfile`。

### 6. #6 系统兼容性（模型适配层）
- 调度决策"用模型 m" → #6 适配层统一调用多种 LLM。角色/模型增删时同步资源环境。

### 7. #5 神经符号容错
- 调度"不可行 → 回送重规划""节点失效 → 重调度"是 #5 容错的入口。

### 8. 输出方向：#7 评测 + #8 可视化
- `ScheduleLogger` 的 JSONL 事件日志喂 #7 评测脚本和 #8 可视化。

## 五、数据结构速查

```python
# 输入（规划器产出）
Subtask(id, scale: ComputeScale, latency_tier: LatencyTier,
        sensitivity: SensitivityLevel,
        est_input_tok, est_output_tok, depends_on)

# 输出（调度决策）
ScheduleDecision(subtask_id, layer_name, model_name,
                 split: SplitPlan | None, latency_ms, cost, feasible, reason)

# 切分方案
SplitPlan(mode='layer'|'phase', block_allocation, phase_layers, model_name)

# 执行结果（执行框架回传）
ExecutionResult(success, latency_ms, cost, tokens)
```

**枚举**：`ComputeScale` S0-S3 | `LatencyTier` T0-T3 | `SensitivityLevel` L0(公开)-L3(机密，L2禁云/L3仅端)

## 八、集成顺序建议

1. 标定 `default_env.json` 真实算力。
2. 接 #4 异构模型集（填入 Φ_ℓ / ModelProfile）。
3. 接执行框架（实现 `ExecutorPort`），跑 `sim` 确认端到端通。
4. 接规划器 DAG，传给 `SchedulerRuntime.run(dag)`。
5. 接 #6 适配层 → 真实 LLM 调用。
6. 把 `ScheduleDecision` 接 #3 路由与 #5 容错。
7. #1 记忆按需接入。
8. 事件日志接 #7 评测 + #8 可视化。
