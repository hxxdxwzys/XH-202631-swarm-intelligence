# CAMEL: Communicative Agents for Mind Exploration of LLM Society

> [!info] 元信息
> - **ArXiv**: `2303.17760`
> - **作者 / 年份**: Guohao Li et al. (KAUST) / 2023
> - **主题分类**: [[agent-framework]]
> - **本地文本**: [2303.17760.txt](file:///../_pdf_text/2303.17760.txt)

## 一句话总结
提出"角色扮演 + 起始提示(inception prompting)"的多 agent 协作框架，让两个 communicative agent（如 AI 用户 + AI 助手）在最少人类干预下自主对话完成任务，并借此大规模生成任务导向对话数据。

## 问题与动机
聊天式 LLM 完成复杂任务严重依赖人类持续引导，费时且需领域专长。能否用自主 communicative agent 替代人类引导，让多 agent 自主协作完成任务？

## 核心方法
- **角色扮演框架**：分配角色（AI user / AI assistant），用 inception prompting 约束双方行为朝任务完成推进、保持与人类意图一致。
- 应对自主协作中的失败模式：角色翻转、助手重复指令、flake 回复、消息无限循环。
- 开源库 + 大规模数据集（AI Society、Code 等），用于研究 agent 社会行为与对齐风险（含 Misalignment 数据集）。

## 关键贡献
- 早期提出可扩展的多 agent 自主协作框架与 inception prompting 对齐技术。
- 用角色扮演大规模生成对话数据，开启"agent 社会"研究范式。

## 实验与数据
偏框架/数据贡献；定性展示角色扮演完成编程、交易等任务，并分析失败模式与对齐风险。无单一强定量基准。

## 局限与不足
- 双 agent 线性对话，拓扑静态；易陷入循环/角色漂移；无动态路由与低熵通信设计；任务复杂度有限。

## 与赛题关联
> 赛题四大支柱：长程记忆 / 动态拓扑低熵通信 / 端边云调度 / 鲁棒容错。
CAMEL 揭示了多 agent 自由通信的典型病——无限循环、重复、角色漂移——正是赛题要抑制的"巴别塔"噪声。其 inception prompting（用结构化约束规范 agent 行为）可作为低熵通信协议的参考；但其静态双 agent 拓扑恰是赛题要摒弃的范式，需升级为动态异构图。
