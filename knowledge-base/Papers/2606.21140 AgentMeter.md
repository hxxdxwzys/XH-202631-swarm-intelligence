# AgentMeter: Model-CLI Matching Benchmark

> [!info] 元信息
> - **ArXiv**: `2606.21140`
> - **作者 / 年份**: Han Chi et al. (中科院网络信息中心/杭州高研院) / 2026
> - **主题分类**: [[benchmark]]
> - **本地文本**: [2606.21140.txt](file:///../_pdf_text/2606.21140.txt)

## 一句话总结
提出 AgentMeter 评测"模型-CLI 匹配"：CLI 不仅是传输层，还中介 prompt 布局/上下文回放/工具输出序列化/停止行为，同一模型在不同 CLI 下成功率/token/成本差异巨大；提出成功锚定、成本感知的 AMS 指标与 Benchmark90/Core30。

## 问题与动机
本地 CLI agent 的部署单元是"模型-CLI 配置"，但既有评测只看任务成功，忽视 CLI 中介作用——同一模型在不同 CLI 下表现迥异，成功/token/成本可能选出不同配置。

## 核心方法
- 把模型-CLI 匹配形式化为评测问题。
- Benchmark90（全验证集）+ Core30（低成本子集），覆盖终端/本地工作流/数据分析任务。
- **AgentMeter Score (AMS)**：成功锚定、成本感知、按校准任务努力分层的匹配指标，结合任务质量、成本预算质量、昂贵失败惩罚。
- 24 个完整模型-CLI 配置对比。

## 关键贡献
- 首个以"部署模型-CLI 配置"为评测单元、兼顾成功与成本的基准与指标。
- 证明模型选择与 CLI 选择不可解耦，应作为整体评测。

## 实验与数据
- Core30：最高 Pass/30、最低 Tok/Pass、最低 USD/Pass、最高 AMS 选出不同配置；Benchmark90 保持 Top-1/Top-3，Spearman 0.765。

## 局限与不足
- 聚焦 CLI 本地任务；单 agent；未涉及多智能体协作与动态拓扑。

## 与赛题关联
> 赛题四大支柱：长程记忆 / 动态拓扑低熵通信 / 端边云调度 / 鲁棒容错。
AgentMeter 是赛题执行引擎(#4 ACI/工具接口)与效率评测(#5)的参照："接口/CLI 中介显著影响成功率与成本"呼应 [[2405.15793 SWE-agent]] 的 ACI 思想。其成本感知 AMS 指标可启发赛题"token/时间效率"打分的设计——不仅看成功，还看昂贵失败与成本。建议赛题评测把"模型+执行接口"作为整体单元。
