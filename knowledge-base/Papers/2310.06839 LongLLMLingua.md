# LongLLMLingua: Long-Context Prompt Compression

> [!info] 元信息
> - **ArXiv**: `2310.06839`
> - **作者 / 年份**: Huiqiang Jiang et al. (Microsoft) / 2023
> - **主题分类**: [[memory-longcontext]]
> - **本地文本**: [2310.06839.txt](file:///../_pdf_text/2310.06839.txt)

## 一句话总结
针对长上下文三大挑战（高成本、性能下降、位置偏差），提出问题感知的 coarse-to-fine 压缩 + 文档重排，提升关键信息密度，同时降本降延迟——在 NaturalQuestions 上用约 1/4 token 提升 21.4%。

## 问题与动机
长上下文场景下 LLM 面临：① 计算成本高；② 冗余噪声削弱性能；③ 位置偏差（"lost in the middle"）。既有压缩法不感知问题，保留过多噪声。

## 核心方法
- **问题感知 coarse-to-fine 压缩**：用小 LM 捕捉与问题相关的关键信息分布，提高密度。
- **文档重排**：把关键信息移到首尾，缓解位置偏差。
- **动态压缩比**：精确控制粗/细压缩级别。
- **压缩后子序列恢复**：提升关键信息完整性。

## 关键贡献
- 首个问题感知的长上下文压缩，同时解成本、性能、位置偏差。
- 压缩后性能反升、成本延迟双降。

## 实验与数据
- NaturalQuestions：GPT-3.5 用约 4x 更少 token 提升 21.4%；LooGLE 成本降 94%；10k token 2-6x 压缩，端到端延迟加速 1.4-2.6x。

## 局限与不足
- 依赖小模型前向打分；重排假设已知相关性；对实时流式场景适配有限；压缩可能丢边缘细节。

## 与赛题关联
> 赛题四大支柱：长程记忆 / 动态拓扑低熵通信 / 端边云调度 / 鲁棒容错。
LongLLMLingua 几乎是为赛题"上下文压缩唤醒"定制：问题感知压缩 + 重排缓解 lost-in-the-middle，正好实现"不依赖单一模型长窗口无损外推"。执行引擎(#4)与记忆层(#3)可用它压缩唤醒的上下文，把最相关信息置于首尾、降低 token 与噪声——直接服务长程记忆与效率两项打分。
