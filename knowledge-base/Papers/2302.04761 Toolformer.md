# Toolformer: Language Models Can Teach Themselves to Use Tools

> [!info] 元信息
> - **ArXiv**: `2302.04761`
> - **作者 / 年份**: Timo Schick et al. (Meta AI) / 2023
> - **主题分类**: [[tool-use]]
> - **本地文本**: [2302.04761.txt](file:///../_pdf_text/2302.04761.txt)

## 一句话总结
让 LLM 自监督地学会"何时调用哪个 API、传什么参数、如何把结果融入后续生成"，仅需少量示范即可掌握计算器、问答、搜索、翻译、日历等工具，且不损失语言建模能力。

## 问题与动机
LLM 缺乏时效信息、易幻觉、算术差、不识时间。给 LLM 加工具通常需大量人工标注或绑定特定任务，难以通用。希望模型自己学会用工具。

## 核心方法
自监督三步：
1. 让 LM 在语料上为各位置采样候选 API 调用；
2. 执行这些调用，用"调用结果是否降低后续 token 的损失"作过滤信号，保留有用的调用；
3. 把保留的 API 调用交织回文本，微调 LM 自身。
模型由此自主决定用哪个工具、何时用、参数与结果融合。

## 关键贡献
- 提出自监督的工具学习范式，模型自学用工具、不挑任务、不丢通用性。
- 在下游任务 zero-shot 表现大幅提升，可匹敌更大模型。

## 实验与数据
- 工具：计算器、QA、搜索、机器翻译、日历；多任务 zero-shot 显著优于不用工具的基线。

## 局限与不足
- 需微调；工具集需预定义；API 调用错误仍可能传播；未涉及多 agent 协作与长程规划。

## 与赛题关联
> 赛题四大支柱：长程记忆 / 动态拓扑低熵通信 / 端边云调度 / 鲁棒容错。
Toolformer 示范了"模型自主决定工具调用"的范式，是赛题执行引擎(#4 工具调用)中"智能体按语义选工具"的参考；其"以损失为信号筛选有用调用"可启发低熵通信——只传递对后续预测真正有用的信息，天然抑制冗余。
