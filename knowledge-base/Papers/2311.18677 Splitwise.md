# Splitwise: Efficient LLM Inference via Phase Splitting

> [!info] 元信息
> - **ArXiv**: `2311.18677`
> - **作者 / 年份**: Pratyush Patel et al. (UW/Microsoft) / 2024
> - **主题分类**: [[inference-serving]]
> - **本地文本**: [2311.18677.txt](file:///../_pdf_text/2311.18677.txt)

## 一句话总结
把 LLM 推理的两个阶段——计算密集的 prompt 计算(prefill) 与访存密集的 token 生成(decode)——分到不同机器，按阶段特征做专用资源管理，经高速互联传 KV 状态，提升吞吐并降本降功耗。

## 问题与动机
单请求推理含两相异构阶段：prefill 计算密集、decode 访存密集且算力利用不足。同机混跑导致延迟不一致、需过度配置昂贵 GPU；而 GPU 算力增长快于显存带宽/容量，加剧失衡。

## 核心方法
- **Phase splitting**：prefill 与 decode 分到不同机器，各配适配硬件。
- 通过背板互联（Infiniband）+ 优化网络库高效传输缓存的上下文(KV) 状态。
- 设计同构/异构推理集群，针对吞吐/成本/功耗优化。

## 关键贡献
- 系统化提出推理阶段分离（预填/解码解耦），成为后续 disaggregated serving 主线。
- 证明按阶段专用资源可同时提升吞吐、降本、降功耗。

## 实验与数据
- 比当前设计吞吐最高 1.4x、成本降 20%；同功耗/成本下吞吐 2.35x。

## 局限与不足
- 需高速互联传 KV；跨机状态传输增加复杂度；面向服务集群而非端边；对单 agent 长程任务调度未涉及。

## 与赛题关联
> 赛题四大支柱：长程记忆 / 动态拓扑低熵通信 / 端边云调度 / 鲁棒容错。
Splitwise 是赛题"端-边-云异构资源自适应调度"与"模型切分"的工业级参照：按推理阶段特征把计算放到合适节点。其 prefill/decode 分离思想可迁移到赛题推理位置动态选择——重计算子任务上云、轻量 decode 可在边/端。与 [[2401.09670 DistServe]]、[[2209.01188 PETALS]] 共同构成端边云调度文献簇。
