# AgentVerse: Facilitating Multi-Agent Collaboration

> [!info] 元信息
> - **ArXiv**: `2308.10848`
> - **作者 / 年份**: Weize Chen et al. (清华/BUPT/Tencent) / 2023
> - **主题分类**: [[agent-framework]]
> - **本地文本**: [2308.10848.txt](file:///../_pdf_text/2308.10848.txt)

## 一句话总结
模拟人类群体解题的四阶段多 agent 框架：专家招募→协同决策→动作执行→评估，并允许依据进展动态调整组成员，超越单 agent 并涌现协作行为。

## 问题与动机
复杂真实任务需多人协作。既有研究多聚焦单一有限任务、且 agent 角色与能力静态僵化，缺乏适应性，泛化性存疑。

## 核心方法
四阶段循环：
1. **Expert Recruitment**：依解题进展动态确定/调整 agent 组成员构成；
2. **Collaborative Decision-Making**：所选 agent 联合讨论制定策略；
3. **Action Execution**：与环境交互执行；
4. **Evaluation**：评估当前态与目标差距，不满意则反馈下一轮。
关键：组成员**动态调整**（区别于静态组队）。

## 关键贡献
- 提出"动态招募专家组"的多 agent 框架，向"摒弃静态组队"迈出一步。
- 在文本理解/推理/编码/工具/具身多域验证，并分析涌现协作行为。

## 实验与数据
- 多 agent 组优于单 agent；揭示特定协作行为的涌现与群体效率提升（定性+定量）。

## 局限与不足
- 招募与决策仍偏启发式；通信拓扑未真正图化、仍偏自由讨论；低熵通信与长程记忆未深入；评估偏案例。

## 与赛题关联
> 赛题四大支柱：长程记忆 / 动态拓扑低熵通信 / 端边云调度 / 鲁棒容错。
AgentVerse 的"动态招募专家 + 评估反馈循环"直接呼应赛题"动态异构拓扑"与"感知-规划-执行-反馈闭环"打分点：agent 角色随任务进展动态生成而非预设。可作为赛题动态组队的起点，但需把"招募"升级为基于图结构路由的稀疏拓扑，并引入结构化通信与容错。
