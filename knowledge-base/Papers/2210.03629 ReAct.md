# ReAct: Synergizing Reasoning and Acting in Language Models

> [!info] 元信息
> - **ArXiv**: `2210.03629`
> - **作者 / 年份**: Shunyu Yao et al. (Princeton / Google) / 2023
> - **主题分类**: [[tool-use]]
> - **本地文本**: [2210.03629.txt](file:///../_pdf_text/2210.03629.txt)

## 一句话总结
让 LLM 以"推理轨迹(reasoning trace) 与 任务动作(action) 交错"的方式工作：推理帮助规划与异常处理，动作接入外部工具/环境获取信息，二者协同显著优于纯推理或纯动作。

## 问题与动机
此前推理（CoT）与动作（action plan）被分开研究。纯推理易幻觉、错误传播且无法获取外部信息；纯动作缺乏目标跟踪与计划调整。人脑中"内心言语"与"行动"是紧耦合的。

## 核心方法
- **Thought → Action → Observation 交错循环**：模型先思考(Thought)决定下一步，发出动作(Action)调用工具（如 Wikipedia 搜索 API），观察结果(Observation)再进入下一轮思考。
- 仅需 1–2 个 in-context 示例即可工作；推理轨迹使过程可解释。

## 关键贡献
- 奠定 LLM agent 的"思考-行动-观察"主循环范式，至今仍是 agent 标准骨架。
- 证明推理与动作的协同可同时降低幻觉、提升可解释性与决策成功率。

## 实验与数据
- HotpotQA、Fever（QA/事实验证）：通过 Wikipedia API 交互，缓解 CoT 幻觉与错误传播。
- ALFWorld +34%、WebShop +10% 绝对成功率，超越模仿/强化学习基线。

## 局限与不足
- 单 agent 线性循环，无多智能体协作；长程任务下轨迹膨胀、上下文易爆；动作空间需预定义。

## 与赛题关联
> 赛题四大支柱：长程记忆 / 动态拓扑低熵通信 / 端边云调度 / 鲁棒容错。
ReAct 循环是赛题执行引擎(#4 工具调用/执行)的范式底座：Thought→Action→Observation 即"规划→工具执行→反馈"闭环。其"推理帮助处理异常"正契合鲁棒容错支柱。但单体循环需扩展为多 agent 异构拓扑，并用结构化消息协议压缩轨迹以实现低熵通信。
