# Are We Ready For An Agent-Native Memory System?

> [!info] 元信息
> - **ArXiv**: `2606.24775`
> - **作者 / 年份**: Wei Zhou et al. (上交/清华/MemTensor) / 2026
> - **主题分类**: [[memory-longcontext]]
> - **本地文本**: [2606.24775.txt](file:///../_pdf_text/2606.24775.txt)

## 一句话总结
从数据管理视角系统评测 agent 记忆：把记忆分解为表征存储/抽取/检索路由/维护四模块，评 12 个代表系统+2 基线跨 5 工作负载/11 数据集，发现无单一架构通吃、效果取决于结构与负载瓶颈对齐，局部维护比全局重组更省，指明 agent-native 记忆方向。

## 问题与动机
agent 记忆已从简单 RAG 演化为支持持久存储/检索/更新/整合/生命周期治理的数据管理系统，但既有评测用端到端任务成功把系统当黑盒，忽视运营成本、模块间架构权衡与动态更新鲁棒性。

## 核心方法
- 分析框架：记忆四模块——表征与存储、抽取、检索与路由、维护。
- 评 12 系统+2 基线，跨 5 工作负载/11 数据集。
- 细粒度消融：表征保真、检索精度、更新正确性、长程稳定性。
- 四类典型架构：流式日志(MemoryBank)、分层分级(MemGPT)、知识图谱(Mem0/Zep)、复合混合(A-MEM)。

## 关键贡献
- 从数据管理视角系统比较 agent 记忆架构，给出四模块分解与成本-性能权衡。
- 揭示"无单一架构通吃""局部维护更省"等实操结论。

## 实验与数据
- 12 系统+2 基线跨 5 负载/11 数据集；局部维护比全局重组更成本高效。

## 局限与不足
- 评测性研究；工作负载有限；与多 agent 动态拓扑/端边云未结合。

## 与赛题关联
> 赛题四大支柱：长程记忆 / 动态拓扑低熵通信 / 端边云调度 / 鲁棒容错。
本文是赛题记忆层(#3)架构选型与评测的总览：四模块分解（存储/抽取/检索路由/维护）可作为赛题记忆子系统设计骨架，四类典型架构（流式/分级/图谱/混合）即赛题可选范本。其"局部维护更省""无单一架构通吃"指导赛题按负载瓶颈选型。与 [[2507.03724 MemOS]]、[[2504.19413 Mem0]]、[[2310.08560 MemGPT]]、[[2606.22877 DynamicMem]] 形成长程记忆评测-架构簇。
