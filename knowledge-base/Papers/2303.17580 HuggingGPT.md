# HuggingGPT (JARVIS)

> [!info] 元信息
> - **ArXiv**: `2303.17580`
> - **作者 / 年份**: Yongliang Shen et al. (Zhejiang Univ. / MSRA) / 2023
> - **主题分类**: [[agent-framework]]
> - **本地文本**: [2303.17580.txt](file:///../_pdf_text/2303.17580.txt)

## 一句话总结
以 LLM 为控制器，把用户请求拆成子任务，按模型功能描述从 Hugging Face 选择并调度专家模型执行，再汇总结果——用语言作为连接 LLM 与海量 AI 模型的统一接口。

## 问题与动机
单一 LLM 无法处理视觉/语音等多模态、不擅长多子任务调度、且常弱于领域专家微调模型。希望让 LLM 协调外部专家模型共同完成复杂跨域任务。

## 核心方法
四阶段流水线：
1. **任务规划**：LLM 把请求分解为结构化任务列表（含依赖、类型）；
2. **模型选择**：根据各模型的功能描述为每子任务选模型；
3. **任务执行**：调用所选模型执行；
4. **响应生成**：LLM 汇总执行结果回应用户。
关键思想："语言作为通用接口"描述模型能力，使 LLM 能在百万级模型库中选型。

## 关键贡献
- 确立"LLM-as-controller + 异构专家模型编排"范式，跨语言/视觉/语音统一调度。
- 提出用模型文档作为可检索的能力描述，支撑大规模工具选型。

## 实验与数据
在语言、视觉、语音等多模态复杂任务上取得令人印象深刻的结果（偏系统/定性，含跨模态组合任务）。

## 局限与不足
- 顺序流水线、依赖 LLM 规划质量；模型描述需高质量维护；延迟与 token 成本高；缺乏容错与重规划机制；端到端长程鲁棒性不足。

## 与赛题关联
> 赛题四大支柱：长程记忆 / 动态拓扑低熵通信 / 端边云调度 / 鲁棒容错。
HuggingGPT 的"LLM 控制器 + 按能力描述路由到异构专家"正是赛题动态异构拓扑的原型：把任务按语义分发到不同能力节点。其"模型功能描述作为可检索接口"可直接借鉴为低熵通信中的能力注册表。但需把静态四阶段流水线升级为动态图、并补足容错与端边云放置决策。
