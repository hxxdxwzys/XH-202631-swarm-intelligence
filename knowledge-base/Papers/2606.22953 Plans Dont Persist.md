# Plans Don't Persist: Context Management Is Load Bearing

> [!info] 元信息
> - **ArXiv**: `2606.22953`
> - **作者 / 年份**: Aman Mehta, Anupam Datta (Snowflake AI Research) / 2026
> - **主题分类**: [[memory-longcontext]]
> - **本地文本**: [2606.22953.txt](file:///../_pdf_text/2606.22953.txt)

## 一句话总结
用 replay pairing 诊断发现：标准 LLM agent 不把计划作为持久内部状态携带，而是依赖计划留在上下文中被每步重读；计划信号在一步内骤降，朴素计划驱逐使 ALFWorld 成功率降 34.7pp，且 probe 门控的重浮现也无法恢复——上下文管理是承重的，但仅保护计划不够。

## 问题与动机
长程 agent 靠压缩/摘要/驱逐旧 token 跨越有限窗口，前提是丢弃信息不再需要或已内化。计划是最尖锐案例：早写、用多步、最先被驱逐——若计划只在上下文而非内部状态，驱逐会悄悄破坏 agent。

## 核心方法
- **Replay pairing**：同一轨迹两条件——A 保留计划、B 移除计划，测各步隐状态余弦距离作为计划保真信号。
- 严格剥离处理推理模型的 imd traces 污染。
- 压力测试：朴素计划驱逐 vs probe 门控重浮现对成功率影响。

## 关键贡献
- 证明 agent 关键信息（计划）是"上下文驻留"而非"持久状态"，上下文管理承重。
- 揭示朴素计划驱逐的巨大代价（-34.7pp）且仅保护计划不够。

## 实验与数据
- Llama-3.1-70B ReAct ALFWorld：计划信号 step+1 达 0.453，一步降 4.1x，step+5 近 0.027；HotpotQA 降 12.4；L32 probe AUROC 0.999；R1 严格剥离 +163%；朴素驱逐 ALFWorld -34.7pp。

## 局限与不足
- 表征性声明非行为；probe 含 step index 混淆未完全控制；面向 ReAct 类 agent。

## 与赛题关联
> 赛题四大支柱：长程记忆 / 动态拓扑低熵通信 / 端边云调度 / 鲁棒容错。
本文是赛题"上下文压缩唤醒"与"长程目标不漂移"的关键警示：压缩/驱逐若不当会丢失计划等承重信息，导致"规划幻觉"。其结论直接指导赛题记忆层(#3)与执行引擎(#4)：关键全局目标/计划必须显式持久化并周期性重唤醒，不能只靠上下文窗口。与 [[2606.22936 Premature Commitment in LLM Agents]]、[[2307.03172 Lost in the Middle]] 共同构成"长程隐性失效"诊断簇。
