# PETALS: Collaborative Inference and Fine-tuning of Large Models

> [!info] 元信息
> - **ArXiv**: `2209.01188`
> - **作者 / 年份**: Alexander Borzunov et al. (HSE/Yandex/HF/UW) / 2022
> - **主题分类**: [[inference-serving]]
> - **本地文本**: [2209.01188.txt](file:///../_pdf_text/2209.01188.txt)

## 一句话总结
让多方在互联网上共建大模型推理/微调：每个参与方只持有模型的一部分层（Transformer block），客户端把请求沿"服务器链"做流水线并行，从而在消费级 GPU 上跑 176B 模型。

## 问题与动机
100B+ 参数模型（BLOOM-176B、OPT-175B）推理需 350GB+ 显存，多数研究者无力承担；RAM/SSD offloading 延迟过高（单 token 5.5–22s）；商用 API 灵活性差且贵。

## 核心方法
- **流水线并行 + 众包**：服务器各持一部分层；客户端选一串服务器组成 pipeline-parallel 链完成整模型前向。
- 支持通过 adapter / prompt tuning 做参数高效微调，子模块可在 model hub 共享。
- 优化：动态量化、低延迟连接优先、服务器间负载均衡；暴露 hidden states 供研究。

## 关键贡献
- 提出"层切分到异构节点 + 流水线并行"的协同推理范式，把大模型推理民主化到消费级硬件。
- 证明模型切分与跨节点调度可行——直接对应赛题"端-边-云模型切分"。

## 实验与数据
- BLOOM-176B 在消费级 GPU 上 ≥1 step/s，可支持交互式应用；优于 offloading。

## 局限与不足
- 依赖参与者在线与带宽；跨节点通信延迟与故障处理是难点；层切分粒度粗，不适合任意子任务级调度。

## 与赛题关联
> 赛题四大支柱：长程记忆 / 动态拓扑低熵通信 / 端边云调度 / 鲁棒容错。
PETALS 是赛题"端-边-云异构资源自适应调度"的范式参照：把模型按层切分到异构节点、按延迟动态选路。其"客户端选最优服务器链"思想可直接迁移到赛题的推理位置动态选择与模型切分；其节点失效场景也呼应鲁棒容错支柱（某节点掉线需重选链路）。
