# ChatDev: Communicative Agents for Software Development

> [!info] 元信息
> - **ArXiv**: `2307.07924`
> - **作者 / 年份**: Chen Qian et al. (清华/悉尼大学/BUPT/Modelbest) / 2023
> - **主题分类**: [[software-engineering]]
> - **本地文本**: [2307.07924.txt](file:///../_pdf_text/2307.07924.txt)

## 一句话总结
把软件开发拆为设计/编码/测试阶段，用"chat chain"规定多 agent 沟通什么、用"communicative dehallucination"规定怎么沟通，让扮演不同角色的 LLM agent 通过多轮对话协作交付完整软件。

## 问题与动机
传统深度学习方法只优化瀑布模型的某一阶段，各阶段技术不一致导致流程割裂。LLM 多 agent 角色扮演可统一各阶段，但自由对话易产生 coding hallucination（代码不完整/不可执行/不准确）。

## 核心方法
- **Chat chain**：把每个阶段再分为更小子任务，串成链式工作流，指导 agent "沟通什么"。
- **Communicative dehallucination**：agent 在直接回答前主动追问更多细节，规范"怎么沟通"，精确交换信息、降低编码幻觉。
- 自然语言利于系统设计，编程语言利于调试——语言作为跨阶段统一桥梁。

## 关键贡献
- 提出 chat chain + 去幻觉通信的多 agent 软件开发范式，端到端从需求到可运行软件。
- 验证结构化通信对抑制多 agent 幻觉的作用。

## 实验与数据
构建需求描述数据集；定性+定量展示 ChatDev 显著改善软件质量与可用性（具体数值随版本更新）。

## 局限与不足
- 链式工作流偏静态；角色固定；去幻觉机制有限；复杂大型软件工程能力受限；通信仍偏自然语言。

## 与赛题关联
> 赛题四大支柱：长程记忆 / 动态拓扑低熵通信 / 端边云调度 / 鲁棒容错。
ChatDev 的"chat chain 规定沟通什么 + 去幻觉规定怎么沟通"正是赛题低熵通信的早期实践：用结构化协议约束 agent 间信息，抑制噪声。其软件工程场景也是赛题两大候选演示场景之一（系统级软件工程自动化）的范本。但需把静态链升级为动态拓扑、并补足容错与重规划。
