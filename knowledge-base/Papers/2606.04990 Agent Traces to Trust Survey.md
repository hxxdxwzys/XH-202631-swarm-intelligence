# From Agent Traces to Trust: Provenance Survey

> [!info] 元信息
> - **ArXiv**: `2606.04990`
> - **作者 / 年份**: Yiqi Wang et al. (Griffith/江苏大学/USQ/北大/南大/悉尼/南科大) / 2026
> - **主题分类**: [[survey]]
> - **本地文本**: [2606.04990.txt](file:///../_pdf_text/2606.04990.txt)

## 一句话总结
把 agent 执行建模为完整类型化 provenance 图、证据追踪为其在证据支持关系上的投影，统一检索 grounding、claim 支持、工具安全、记忆谱系、可观测、调试、审计、恢复于一个框架，梳理 trace 来源、provenance 关系、信任功能与开放挑战。

## 问题与动机
agent 自主性增强使行为难验证/调试/审计；终答案准确率无法解释输出来源、证据支持、工具调用合理性、记忆影响或失败定位——存在过程级问责缺口。

## 核心方法
- **执行 provenance**：agent 执行的完整类型化图（检索文档/工具调用/参数/观测/记忆访问/中间claim/动作/agent 间消息/最终输出）。
- **证据追踪**：provenance 图在证据支持关系上的投影。
- 借鉴 W3C PROV-DM、OpenTelemetry、AgentOps/AgentTrace。
- taxonomy：trace 来源、证据/执行单元、provenance 关系、追踪粒度/时机、表示形式、信任功能。

## 关键贡献
- 用 provenance 图统一 agent 行为的验证/归因/调试/安全/审计/恢复。
- 推动评测从"终答案正确"走向"过程级问责"。

## 实验与数据
综述性，无单一实验；提供 taxonomy、代表系统映射与基准/数据集梳理。

## 局限与不足
- 综述性，偏概念；统一 trace schema 与语义 provenance 仍开放；工程落地需后续。

## 与赛题关联
> 赛题四大支柱：长程记忆 / 动态拓扑低熵通信 / 端边云调度 / 鲁棒容错。
本文是赛题执行引擎(#4 日志/可观测)与"展示推理轨迹"交付物的核心理论参照：provenance 图即结构化日志/推理轨迹的规范形态。其"过程级问责"思想可直接用于赛题日志设计（每次 dispatch/工具调用/重试/消息都带类型化 provenance），并服务鲁棒容错的失败定位与恢复。是赛题日志体系的方法学基线。
