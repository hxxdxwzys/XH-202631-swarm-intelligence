# Agent Laboratory: LLM Agents as Research Assistants

> [!info] 元信息
> - **ArXiv**: `2501.04227`
> - **作者 / 年份**: Samuel Schmidgall et al. (AMD/JHU/ETH) / 2025
> - **主题分类**: [[agent-framework]]
> - **本地文本**: [2501.04227.txt](file:///../_pdf_text/2501.04227.txt)

## 一句话总结
自主 LLM agent 框架，接受人类研究 idea，经文献综述→实验→报告写作三阶段产出代码库与研究报告，支持各阶段人类反馈；o1 驱动产出最佳，且比此前自主研究方法降本 84%。

## 问题与动机
科学发现耗时昂贵；希望加速研究、降本提质，让研究者专注创意而非低层编码与写作。LLM 在 idea 生成上有潜力但可行性与实现细节仍弱，应定位为辅助而非替代。

## 核心方法
- 三阶段 pipeline：文献综述、实验、报告写作，产出代码仓库+研究报告。
- 各阶段可注入人类反馈（co-pilot 模式），按用户偏好调频率。
- 计算灵活：按用户算力与推理预算分配。
- 部署多种 SOTA LLM 对比。

## 关键贡献
- 端到端研究自动化 pipeline，强调人在回路辅助。
- 证明人类反馈显著提质、成本大幅下降。

## 实验与数据
- o1-preview 产出最佳；生成 ML 代码可达 SOTA；人类反馈显著提质；比此前自主方法降本 84%。自动评测高估质量（6.1 vs 3.8）。

## 局限与不足
- pipeline 偏线性静态；非多 agent 动态协作；研究质量依赖 LLM 与人类反馈；领域偏 ML 研究。

## 与赛题关联
> 赛题四大支柱：长程记忆 / 动态拓扑低熵通信 / 端边云调度 / 鲁棒容错。
Agent Laboratory 是赛题"跨域多模态投研"演示场景的范本：从高层意图到研究报告+代码的长程闭环。其三阶段 pipeline 与人在回路可映射赛题任务编排。但需把线性 pipeline 升级为动态多 agent 拓扑，并补足记忆与容错以支持更长程任务。
