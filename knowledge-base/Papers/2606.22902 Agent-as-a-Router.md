# Agent-as-a-Router (ACRouter): Agentic Model Routing

> [!info] 元信息
> - **ArXiv**: `2606.22902`
> - **作者 / 年份**: Pengfei Zhou et al. (NUS/阿里DAMO/UCB/HKUST/浙大) / 2026
> - **主题分类**: [[topology-communication]]
> - **本地文本**: [2606.22902.txt](file:///../_pdf_text/2606.22902.txt)

## 一句话总结
指出模型路由的瓶颈是"信息赤字"而非推理能力，把路由形式化为 Context-Action-Feedback 循环：路由器在部署中积累执行接地经验，由 Orchestrator+Verifier+Memory 组成 ACRouter，在 CodeRouterBench(10K 任务/8 前沿模型)上实现最低累积 regret 并泛化到 OOD。

## 问题与动机
用户可访问多 LLM，各擅不同域，需按任务路由；现有路由是静态一次性分类，零样本 LLM 路由器远逊 per-task oracle。消融显示加任务维度性能统计即 +15.3%，证明瓶颈是信息赤字而非推理。

## 核心方法
- 路由形式化为 **C-A-F 循环**：观察 Context(先验+累积经验) → 选 Action(调用哪个模型) → 收到验证 Feedback(分数与成本效率) → 并入下轮 Context。
- 类比 contextual bandit，用累积 regret 作流式指标。
- **ACRouter**：Orchestrator + Verifier + Memory 三模块。
- **CodeRouterBench**：10K 任务/9 ID 编码维度 + OOD agentic-programming，8 前沿模型验证分数。

## 关键贡献
- 把路由从静态分类升级为执行接地、自演化的 agentic 循环，用 regret 评测。
- 证明信息积累是路由性能关键。

## 实验与数据
- ID 任务最低累积 regret；泛化到 OOD agentic-programming；+15.3% 相对增益来自信息而非推理。

## 局限与不足
- 面向编码任务的模型级路由；需验证器与执行环境；与多 agent 拓扑/端边云未结合。

## 与赛题关联
> 赛题四大支柱：长程记忆 / 动态拓扑低熵通信 / 端边云调度 / 鲁棒容错。
Agent-as-a-Router 是赛题"动态路由"的前沿方法：路由器自身是 agent、在执行中积累经验、用 regret 优化——把"路由"从静态分类变为自适应闭环。其 C-A-F 循环与赛题"感知-规划-执行-反馈"闭环同构。可与 [[2502.00409 Routing Strategies Survey]]、[[2403.12031 RouterBench]]、[[2606.17489 Online LLM Selection Bandits]] 形成路由方法簇。
