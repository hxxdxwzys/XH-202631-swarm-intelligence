# Program of Thoughts Prompting

> [!info] 元信息
> - **ArXiv**: `2211.12588`
> - **作者 / 年份**: Wenhu Chen et al. (Waterloo/Vector/UCSB/Google) / 2022
> - **主题分类**: [[reasoning]]
> - **本地文本**: [2211.12588.txt](file:///../_pdf_text/2211.12588.txt)

## 一句话总结
提出 PoT：让 LLM 生成"自然语言推理 + 编程语言语句"，把计算交给程序解释器执行，解耦推理与计算，在数学与金融数值推理上平均超 CoT 约 12%。

## 问题与动机
LLM 不擅长精确计算：① 大数算术易错；② 无法解多项式/微分方程等复杂表达式；③ 难以高效表达长迭代。CoT 把推理与计算都压在 LLM 上，迭代 50 步后正确率趋近于 0。

## 核心方法
- **PoT**：LM 生成文本+程序语句，计算由解释器（含 SymPy 等库）完成。
- 与 PAL 类似但更强调用程序库解决复杂方程与迭代；支持 few-shot 与 zero-shot；可与 self-consistency 组合。

## 关键贡献
- 系统验证"把计算外包给解释器"在数学与金融 QA 上的广泛收益。
- few-shot 下 MWP 平均 +8%、金融数据集 +15%；zero-shot MWP +12%；PoT+SC 比 CoT+SC 平均 +10%。

## 实验与数据
- 数据集：GSM8K、AQuA、SVAMP、TabMWP、MultiArith、FinQA、ConvFinQA、TATQA，普遍显著优于 CoT。

## 局限与不足
- 适用面受限于可程序化的数值/符号任务；程序生成错误仍存在；对纯语言推理无优势。

## 与赛题关联
> 赛题四大支柱：长程记忆 / 动态拓扑低熵通信 / 端边云调度 / 鲁棒容错。
与 [[2211.10435 PAL Program-aided Language Models]] 一致：执行引擎可对数值/金融类子任务走 PoT 路径，用确定性解释器消除 LLM 计算噪声，提升长程鲁棒性与可验证性——呼应赛题"神经符号协同推理"与鲁棒容错。
