# Magentic-One: Generalist Multi-Agent System

> [!info] 元信息
> - **ArXiv**: `2411.04468`
> - **作者 / 年份**: Adam Fourney et al. (Microsoft Research AI Frontiers) / 2024
> - **主题分类**: [[agent-framework]]
> - **本地文本**: [2411.04468.txt](file:///../_pdf_text/2411.04468.txt)

## 一句话总结
通用多 agent 系统：一个 Orchestrator 主导，迭代规划、维护进度工作记忆、分派任务给专门 agent（WebSurfer/FileSurfer/Coder/ComputerTerminal），并在出错时重规划恢复，跨 GAIA/AssistantBench/WebArena 达 SOTA 级。

## 问题与动机
agent 须能在多样场景中规划、多步推理与行动、响应新观察、从错误恢复。需一个不修改核心能力即可泛化的通用 agent 系统。

## 核心方法
- **Orchestrator**：主导 agent，迭代规划 + 进度工作记忆（两个结构化 ledger）+ 分派 + 出错重规划。
- 专门 agent：WebSurfer（浏览器）、FileSurfer（文件）、Coder、ComputerTerminal。
- 模块化：agent 可增删无需重新调 prompt/训练。
- 基于 AutoGen 实现；附 AutoGenBench（含重复与隔离控制的评测工具）。

## 关键贡献
- 强调"Orchestrator 主导 + 出错重规划"的通用范式，显式处理错误恢复。
- 模块化可扩展，跨三大基准竞争性 SOTA。

## 实验与数据
- GAIA/AssistantBench/WebArena 上与 SOTA 统计相当；含消融与错误分析。

## 局限与不足
- 拓扑为 Orchestrator-中心（星型），非动态稀疏图；通信偏自然语言；长程记忆有限；依赖 LLM 重规划质量。

## 与赛题关联
> 赛题四大支柱：长程记忆 / 动态拓扑低熵通信 / 端边云调度 / 鲁棒容错。
Magentic-One 的"Orchestrator 迭代规划+进度记忆+出错重规划"几乎命中赛题"感知-规划-执行-反馈闭环"与鲁棒容错支柱。其两个结构化 ledger 是低熵进度通信的范本。但需把星型 Orchestrator 升级为动态异构图，并补足长程分布式记忆。可作为赛题编排层的参考架构。
