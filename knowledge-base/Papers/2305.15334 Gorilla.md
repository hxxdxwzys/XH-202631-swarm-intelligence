# Gorilla: Large Language Model Connected with Massive APIs

> [!info] 元信息
> - **ArXiv**: `2305.15334`
> - **作者 / 年份**: Shishir G. Patil et al. (UC Berkeley/MSR) / 2023
> - **主题分类**: [[tool-use]]
> - **本地文本**: [2305.15334.txt](file:///../_pdf_text/2305.15334.txt)

## 一句话总结
微调一个 LLaMA-based 模型（Gorilla）使其能在海量、重叠、不断变化的 API 中准确选型与调用，配合文档检索器适应测试时文档变更，并显著降低 API 幻觉。

## 问题与动机
即便 GPT-4 在 API 调用上也常出错：生成错误参数、幻觉不存在的 API 用法。且 API 数量达百万级、功能重叠、版本频繁变化，无法塞进单次上下文。

## 核心方法
- **Self-instruct 微调**：在 API 文档生成的指令数据上微调 LLaMA。
- **文档检索器**：测试时检索相关 API 文档注入上下文，使模型适应文档更新/版本变化。
- 评估基准 **APIBench**：覆盖 TorchHub(94)、TensorHub(696)、HuggingFace(925) API。

## 关键贡献
- 证明"微调+检索"可在海量重叠 API 上实现准确、抗幻觉的工具调用，超越 GPT-4。
- 提出应对"工具空间巨大且动态变化"的检索增强方案与基准 APIBench。

## 实验与数据
- 在 APIBench 上准确率高于 GPT-4，幻觉率更低；检索器带来测试时文档适应性（BM25/GPT/oracle 检索对比）。

## 局限与不足
- 需微调；API 集仍为 ML 模型 API，未覆盖真实业务 API 的鉴权/副作用；调用正确性未在端到端任务中验证；无多 agent 协作。

## 与赛题关联
> 赛题四大支柱：长程记忆 / 动态拓扑低熵通信 / 端边云调度 / 鲁棒容错。
Gorilla 的"能力描述可检索 + 测试时适应文档变更"是赛题工具层的关键参考：异构 agent 的工具注册表应可检索、可热更新。其降低 API 幻觉直接服务鲁棒容错。执行引擎(#4)可借鉴"检索工具文档再调用"以应对动态工具空间，减少调用错误。
