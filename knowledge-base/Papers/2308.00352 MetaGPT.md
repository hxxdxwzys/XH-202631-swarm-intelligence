# MetaGPT: Meta Programming for a Multi-Agent Collaborative Framework

> [!info] 元信息
> - **ArXiv**: `2308.00352`
> - **作者 / 年份**: Sirui Hong et al. (DeepWisdom/KAUST/厦大/CUHK 等) / 2024
> - **主题分类**: [[agent-framework]]
> - **本地文本**: [2308.00352.txt](file:///../_pdf_text/2308.00352.txt)

## 一句话总结
把人类组织的标准作业流程(SOP)编码为提示序列，用流水线范式给 agent 分配异构角色，要求结构化中间产物（PRD、设计、接口规范），显著降低多 agent 级联幻觉。

## 问题与动机
朴素串联 LLM 会因级联幻觉产生逻辑不一致，难以求解复杂任务；自由闲聊式多 agent（"吃午饭了吗"）噪声大、效率低。

## 核心方法
- **SOP 编码**：把人类协作 SOP 编为提示序列，规范各角色职责与中间产物标准。
- **流水线范式**：像装配线一样分配角色（产品经理/架构师/工程师…），分解复杂任务。
- **结构化输出**：要求高质量需求文档、设计图、流程图、接口规范，作为下游输入——减少歧义与幻觉，提升代码生成成功率。

## 关键贡献
- 提出 SOP + 结构化交接的多 agent 框架，把"组织管理思想"显式编码进 agent 系统。
- 在协作软件工程基准上生成比 chat-based 系统更连贯的方案；HumanEval/MBPP 达 SoTA（85.9% 等）。

## 实验与数据
- 代码生成基准 SoTA；协作 SE 基准上超越此前 chat-based 多 agent 系统。

## 局限与不足
- SOP 与角色流偏静态、人工设计；拓扑非动态生成；结构化 schema 需预制；扩展到非 SE 场景需重新设计 SOP。

## 与赛题关联
> 赛题四大支柱：长程记忆 / 动态拓扑低熵通信 / 端边云调度 / 鲁棒容错。
MetaGPT 几乎命中赛题"组织架构与协作机制"打分点：层级分工、SOP、结构化交接抑制噪声级联。其"结构化中间产物"是低熵通信的范本。但赛题要求"摒弃静态组队"——需把 MetaGPT 的静态 SOP 升级为随任务语义动态生成的拓扑与协议。可作为赛题组织层的起点而非终点。
