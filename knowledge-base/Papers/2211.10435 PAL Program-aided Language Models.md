# PAL: Program-aided Language Models

> [!info] 元信息
> - **ArXiv**: `2211.10435`
> - **作者 / 年份**: Luyu Gao et al. (CMU) / 2022
> - **主题分类**: [[reasoning]]
> - **本地文本**: [2211.10435.txt](file:///../_pdf_text/2211.10435.txt)

## 一句话总结
让 LLM 把自然语言问题转写成 Python 程序作为推理步骤，再把"求解"交给解释器执行，从而把推理与计算解耦，显著提升数值/符号推理准确率。

## 问题与动机
CoT 让 LLM 既负责分解又负责计算，但 LLM 在复杂算术与大数计算上极易出错；即使分解正确，计算步仍频繁失误。

## 核心方法
- **PAL**：LLM 读自然语言问题 → 生成 Python 代码作为中间推理步 → 解释器执行代码得答案。
- 分解仍是 LLM 的学习任务，求解完全委托给确定性解释器——典型的神经-符号分工。

## 关键贡献
- 提出"生成程序而非自然语言推理链"的范式，利用解释器消除计算误差。
- 在 13 个 BIG-Bench Hard 等推理任务上，小模型(Codex)+PAL 超越大模型(PaLM-540B)+CoT。

## 实验与数据
- GSM8K：PAL(Codex) 比 PaLM-540B+CoT 高绝对 15% top-1。

## 局限与不足
- 仅适合可程序化的问题；代码生成本身可能错；依赖代码模型；对开放域非数值推理帮助有限。

## 与赛题关联
> 赛题四大支柱：长程记忆 / 动态拓扑低熵通信 / 端边云调度 / 鲁棒容错。
PAL 的"推理与计算解耦、确定性执行器兜底"思想可嵌入赛题执行引擎：数值/逻辑类子任务生成程序由解释器执行，减少 LLM 计算噪声，提升长链鲁棒性；也示范了"工具调用作为推理的一部分"，与 tool-use 支柱互补。
