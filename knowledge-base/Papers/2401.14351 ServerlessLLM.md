# ServerlessLLM: Low-Latency Serverless Inference

> [!info] 元信息
> - **ArXiv**: `2401.14351`
> - **作者 / 年份**: Yao Fu et al. (Edinburgh/NTU) / 2024
> - **主题分类**: [[inference-serving]]
> - **本地文本**: [2401.14351.txt](file:///../_pdf_text/2401.14351.txt)

## 一句话总结
利用推理服务器近 GPU 的多级存储（DRAM/SSD）做本地 checkpoint 缓存，配合加载优化格式、活迁移与启动时延优化的调度，把 serverless LLM 推理冷启动延迟降低 10–200x。

## 问题与动机
Serverless 推理省钱但有严重冷启动：LLM checkpoint 达 GB–TB 级，从远端存储下载延迟高；而 GPU 服务器本地多级存储层级却被现有系统低效利用。

## 核心方法
三大贡献：
1. **快速多级 checkpoint 加载**：加载优化格式 + 多级加载系统，充分利用 GPU 服务器复杂存储层级带宽；
2. **高效活迁移**：新推理利用本地 checkpoint，最小化用户中断；
3. **启动时延优化调度**：依各服务器 checkpoint 局部性状态，把模型调度到启动最快的节点。

## 关键贡献
- 把 serverless LLM 冷启动问题转化为本地多级存储 + 局部性调度问题。
- 端到端降延迟 10–200x。

## 实验与数据
- 跨多种 LLM 推理负载，延迟比 SOTA serverless 系统降 10–200x。

## 局限与不足
- 面向云端 serverless；依赖本地存储容量；checkpoint 一致性管理复杂；未涉及多 agent 协作与长程任务。

## 与赛题关联
> 赛题四大支柱：长程记忆 / 动态拓扑低熵通信 / 端边云调度 / 鲁棒容错。
ServerlessLLM 的"局部性感知调度 + 多级存储缓存"是赛题端边云调度的参考：把模型/状态放到能最快启动的节点，减少冷启动。其活迁移思想直接服务鲁棒容错——节点失效时快速在另一节点拉起。执行引擎(#4)的部署与故障转移可借鉴。
