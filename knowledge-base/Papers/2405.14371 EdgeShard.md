# EdgeShard: Efficient LLM Inference via Collaborative Edge Computing

> [!info] 元信息
> - **ArXiv**: `2405.14371`
> - **作者 / 年份**: Mingjin Zhang, Jiannong Cao et al. (香港理工大学) / 2024
> - **主题分类**: [[inference-serving]]
> - **本地文本**: [2405.14371.txt](file:///../_pdf_text/2405.14371.txt)

## 一句话总结
把 LLM 切分为多个 shard 分布到边缘设备与云服务器协同推理，用动态规划求解"设备选择 + 模型划分"的联合优化问题，最小化推理延迟与吞吐，在 Llama2 上降延迟 50%、吞吐翻倍。

## 问题与动机
LLM 重度依赖云端，带来长延迟、高带宽与隐私问题；纯量化损精度；云-边二分式协作受边缘-云间不稳定网络拖累。边缘算力增长，可做边缘间横向协同。

## 核心方法
- **模型分片(shard)**：把 LLM 切成多个 shard 部署到分布式设备。
- **协同边缘计算(CEC)**：整合地理分布的边缘设备与云形成共享资源池，既纵向(云-边-端)又横向(边-边)协作。
- **联合优化**：把设备选择与模型划分建模为优化问题，设计动态规划算法优化延迟/吞吐。

## 关键贡献
- 提出边缘-云协同的 LLM 分片推理与设备选择联合优化框架。
- 证明横向边缘协同优于纯云-边二分。

## 实验与数据
- Llama2 系列在异构物理原型上：延迟降 50%、吞吐提升 2x。

## 局限与不足
- 面向推理管线，未涉及 agent 任务级调度；设备异构与失效处理未深入；隐私与一致性管理待完善。

## 与赛题关联
> 赛题四大支柱：长程记忆 / 动态拓扑低熵通信 / 端边云调度 / 鲁棒容错。
EdgeShard 几乎是赛题"端-边-云异构资源自适应调度 + 模型切分"的直击之作：模型分片到端/边/云、动态规划选设备与切分点、优化延迟。其"横向边缘协同"契合荣耀终端生态。执行引擎(#4)的调度钩子可直接借鉴其划分-选择联合优化模型。是端边云支柱的必读基线。
