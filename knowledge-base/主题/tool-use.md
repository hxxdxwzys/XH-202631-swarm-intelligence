# 主题：工具调用与行动 (tool-use)

agent 如何接入外部工具/环境——赛题执行引擎(#4)的范式底座。

## 演进主线
1. **模块化路由** [[2205.00445 MRKL Systems]]：路由器+异构专家模块，神经-符号分工先驱。
2. **推理-行动交错** [[2210.03629 ReAct]]：Thought→Action→Observation 主循环，agent 标准骨架。
3. **自学用工具** [[2302.04761 Toolformer]]：自监督决定何时调哪个 API，不挑任务不丢通用性。
4. **语言反思** [[2303.11366 Reflexion]]：失败→语言反思→情景记忆→改进，verbal RL。
5. **海量 API** [[2305.15334 Gorilla]] / [[2307.16789 ToolLLM]]：微调+检索应对百万级动态 API，DFSDT 搜索多轮调用。

## 综合洞察
- **ReAct 循环**是几乎所有 agent 的底座；其"推理帮助处理异常"正契合鲁棒容错。
- **工具空间巨大且动态**（Gorilla/ToolLLM）：必须"检索工具文档再调用"，工具注册表可热更新——赛题执行引擎的工具层关键。
- **Reflexion** 几乎是为赛题自主纠错量身定做：失败反思存记忆、再重试，天然低熵（只留可操作教训）。

## 与赛题关联
> 支柱：鲁棒容错 / 低熵通信
- 执行引擎(#4)的 ACI/工具接口设计参考 ReAct + Gorilla 检索 + Reflexion 反思重试。
- 工具调用结果应**结构化（typed schema）**返回，下游 agent 拿 schema 而非自然语言 dump——低熵通信的物理切断。
- L1 语义失败重试可直接用 Reflexion：生成结构化反思存入记忆再重试或上报。
